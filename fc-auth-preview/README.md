# 우리 가족 달력 · 🏪 매장 달력

가족끼리 실시간으로 함께 쓰는 음력 지원 가족 달력입니다. 휴대폰 브라우저에서 열고 "홈 화면에 추가"하면 앱처럼 쓸 수 있어요.
주소: <https://anarita82.github.io/family-calendar/>

## 이전 버전(테스트)에서 달라진 점

- 저장 위치를 `localStorage`(그 기기에만)에서 **Firebase Cloud Firestore**(가족 공유 DB)로 옮겼습니다.
  한 사람이 일정을 추가·수정·삭제하면 가족 모두의 폰에 `onSnapshot`으로 즉시 반영됩니다.
- 처음 앱을 열 때 **가족 코드**를 한 번 입력하면 그 폰에 기억됩니다(코드를 아는 사람만 같은 달력을 봅니다).
- 한국어 음력·공휴일 계산, 구성원 6인 필터, 5개 카테고리, D-Day 목록 등 기존 기능은 그대로입니다.
- "가족 초대 링크 복사" 버튼으로 `?code=가족코드`가 붙은 링크를 만들어 가족에게 보낼 수 있습니다.
- "샘플 일정 지우기"는 제목이 `[샘플]`로 시작하는 일정만 지웁니다(가족이 넣은 일정은 그대로).

## 구성원·관리자·승인 (2026-11-16 추가)

| 역할 | 사람 | 할 수 있는 일 |
| --- | --- | --- |
| 메인 관리자 | 아빠 | 일정 즉시 등록·수정·삭제, 승인/거절, 구성원 추가·역할 변경, 아빠·엄마 PIN 변경 |
| 부매니저 | 엄마 | 일정 즉시 등록·수정·삭제, 승인/거절, 구성원 추가, 자기 PIN 변경 |
| 일반 구성원 | 외할머니·첫째·둘째·막내 + 추가한 인원 | 일정은 `일정 등록 요청`으로만, 내 이름·번호도 `신상정보 변경 요청`으로만 보낼 수 있고 아빠·엄마 승인 후 반영 |

- 앱을 열면 **"현재 사용자 선택"** 창에서 이 폰을 쓰는 사람을 고릅니다(폰에 기억).
  상단 프로필 배지를 누르면 언제든 바꿀 수 있습니다.
- **아빠·엄마는 4자리 관리자 PIN**을 넣어야 전환됩니다. 처음 PIN은 **`2026`** 이고,
  관리자 설정에서 각각 바꿀 수 있습니다. PIN 평문은 어디에도 저장하지 않고
  `SHA-256(방 ID + 구성원 ID + PIN)` 해시만 Firestore에 둡니다.
- 일반 구성원이 보낸 요청은 `요청 현황`(대기 중/승인됨/거절됨)으로 확인할 수 있고,
  관리자 화면 상단의 **🔔 승인 대기 N건**에서 승인·거절합니다.
  이름·휴대폰 번호 변경도 같은 승인함에서 처리합니다(아래 『구성원·알바생 신상정보 변경 승인제』).

## 구성원·알바생 신상정보 변경 승인제 (2026-11-16 추가)

이름·휴대폰 번호는 **당사자가 바로 바꾸지 못하고, 관리자 승인 뒤에 반영**됩니다.

| 화면 | 요청자 | 하는 일 |
| --- | --- | --- |
| 가족 `🙋 내 정보` | 일반 구성원(외할머니·첫째·둘째·막내·추가 인원) | 이름·번호를 고쳐 저장 → `profileRequests` 에 `pending` 으로 올라감 (members[] 는 그대로) |
| 가족 `🔔 승인 대기` | 아빠(메인 관리자)·엄마(부매니저) | 일반 일정 요청과 함께 **🙋 신상정보 변경 요청**(요청자 · 기존 → 변경)이 보이고, [승인]하면 `members[]` 에 반영·[거절]하면 그대로 |
| 가족 `📨 내 요청 현황` | 요청한 구성원 | 내 변경 요청의 대기 중/승인됨/거절됨을 확인 |
| 가족 `⚙️ 관리자 설정` | 아빠·엄마 | 구성원 이름·번호를 직접 고치면 예전처럼 **즉시** 반영 |
| 매장 `🙋 내 정보` | 알바생 | 이름·번호를 고쳐 저장 → `profileRequests` 에 `pending` (staff[] 는 그대로), 본인 화면에 대기/결과 표시 |
| 매장 `🔔 입장·승인 관리` | 사장님 | 입장 요청과 함께 **🙋 신상정보 변경 요청**이 보이고 [승인] 시 `staff[]` 반영 |
| 매장 `👥 알바생 관리` | 사장님 | 이름·번호를 직접 고치면 **즉시** 반영 |

- 한 사람이 대기 중인 변경 요청은 **1건**입니다. 다시 저장하면 그 요청이 새 내용으로 바뀝니다.
- 승인 시 `members[]`·`staff[]` 의 해당 항목만 이름·번호를 바꾸고, 색·역할·사진·입사일 등 나머지 값은 그대로 둡니다.
  (현재 문서를 트랜잭션 안에서 다시 읽어 적용하므로 그 사이 다른 저장을 지우지 않습니다.)
- 동시 요청 안전성: `requests`·`joinRequests`·`profileRequests` 맵은 **점 경로(dot-notation) 업데이트**로만 고칩니다.
  입장 요청 승인·거절도 맵 전체를 덮어쓰지 않아 다른 대기 요청이 지워지지 않습니다.
- 관리자 PIN은 예전과 같습니다(처음 `2026`).

## 데이터 구조 (Cloud Firestore)

```
rooms/{roomId}
  schema: 2, name: "우리 가족", createdAt
  members: [ { id, name, color, bg, role, tel } ]    // role: admin | manager | member, tel: 휴대폰 번호(선택)
  pins: { dad: "<sha256>", mom: "<sha256>" }     // 4자리 PIN의 해시 (평문 없음)
  requests: {                                    // 일정 등록 요청 (맵 필드)
    <requestId>: { status: pending|approved|rejected, requesterId, requesterName,
                   title, date, time, members[], category, memo, repeat, lunar,
                   createdAt, decidedBy, decidedByName, decidedAt, eventId }
  }
  profileRequests: {                             // 신상정보(이름·번호) 변경 요청 (맵 필드)
    <requestId>: { status: pending|approved|rejected, targetId, requesterId, requesterName,
                   prevName, prevTel, name, tel,
                   createdAt, decidedBy, decidedByName, decidedAt }
  }
  events/{eventId}
    title, date(YYYY-MM-DD), time, members[], category, memo, repeat, lunar, createdAt, updatedAt
```

> 요청을 하위 컬렉션(`rooms/{roomId}/requests`)이 아니라 방 문서의 맵 필드로 둔 이유:
> 현재 게시된 보안 규칙이 `events` 하위 컬렉션만 허용하고, Firebase 콘솔이 재로그인을
> 요구해 규칙을 새로 게시하지 못했습니다. 방 문서 필드는 이미 허용된 경로라 규칙 변경
> 없이 동작하고, 예전 버전 앱은 이 필드를 무시합니다.
> 나중에 규칙을 바꾸게 되면 아래 한 줄을 `match /rooms/{roomId}` 안에 추가하면 됩니다.
> ```
> match /requests/{requestId} { allow read, create, update, delete: if request.auth != null; }
> ```

- `roomId` = `SHA-256("family-calendar-room:" + 가족코드)` 앞 32자리 — 코드 자체는 DB에 저장하지 않습니다.
- 보안 규칙(배포본):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rooms/{roomId} {
      allow get, create, update: if request.auth != null;   // 목록 조회는 막음
      // 구성원·PIN 해시·요청은 이 문서의 필드라 위 규칙으로 함께 커버됩니다.
      match /events/{eventId} {
        allow read, create, update, delete: if request.auth != null;
      }
    }
  }
}
```

- 앱은 **익명 로그인**으로 접속하므로, 로그인하지 않은 요청은 거부되고 방 목록도 조회할 수 없습니다.
  같은 달력을 보려면 가족 코드를 알아야 해당 `roomId`에 접근할 수 있습니다.

## 개인정보

공개 저장소입니다. 가족 실명·생년월일·전화번호·주소는 코드와 DB 어디에도 넣지 않았고, 구성원은 `아빠·엄마·외할머니·첫째·둘째·막내`로만 표시합니다.
Firebase 설정값(apiKey 등)은 웹 앱 식별용 공개 값이며, 접근 통제는 위 보안 규칙이 담당합니다.

## 구성원·알바생 휴대폰 번호 (2026-11-16 추가)

- **가족**: 관리자 설정에서 구성원마다 번호를 넣고(다른 곳을 누르면 저장), 구성원을 추가할 때도 번호를 함께 넣을 수 있어요.
  상단 프로필 배지 → **누구신가요?** 창의 **내 정보**에서 각자 자기 이름·번호를 고쳐 저장합니다.
  일반 구성원의 저장은 **아빠·엄마 승인 뒤에** 반영되고, 아빠·엄마는 바로 반영됩니다.
  구성원 목록에는 등록된 번호가 `📞 010-…`로 보이고 누르면 바로 전화(`tel:`)가 걸려요. 번호가 없으면 `미등록`으로 표시됩니다.
- **매장**: 알바생이 초대 링크로 들어와 이름과 번호를 넣고 입장을 요청하면,
  사장님 **🔔 입장·승인** 카드에 이름·번호가 함께 보이고 승인하면 `staff[]`에 번호가 저장돼요.
  알바생 관리에서 시급처럼 번호를 고칠 수 있고(📞 바로 전화, 사장님이 고치면 바로 반영), 알바생이 자기 화면의 **🙋 내 정보**에서 이름·번호를 고치면 **사장님 승인 뒤에** 반영됩니다.
  근무 카드(사장님 화면)와 급여명세서(화면·카톡 복사본)에도 연락처가 들어갑니다.
- 번호는 `010-1234-5678` / `02-1234-5678` / `1588-1234` / `+82 …` 형태로 자동 정리되고,
  **저장 위치는 Firestore 방 문서(`rooms/{roomId}`)뿐**입니다. 공개 저장소 코드에는 번호가 없습니다.

## 🏪 매장 캘린더 (2026-11-16 추가)

가족 달력과 **같은 앱**에서 상단 탭으로 오가지만, **Firebase 방 자체가 달라** 데이터가 섞이지 않습니다.

- 방 ID 소금(salt)이 다릅니다: 가족 `family-calendar-room:` / 매장 `family-calendar-store-room:`.
  같은 코드를 써도 서로 다른 문서가 됩니다.
- 사장님: 매장 코드를 만들고, 초대 링크를 보내고, 승인·시급·급여명세서를 관리합니다 (PIN, 처음 `2026`).
- 알바생: 초대 링크(`?store=매장코드`)로 들어와 이름을 넣고 **입장 요청** → 사장님 승인 뒤에만 매장 달력이 열립니다.
  알바생 기기에서는 가족 탭이 아예 보이지 않고(`localStorage` 잠금), 가족 방 연결도 하지 않습니다.
- 근무: 알바생·시작/종료 시간·휴게(분)·적용 시급·상태(예정/근무완료/결근/취소)·메모.
  시작일과 종료일을 다르게 넣으면 **여러 날 연속 근무**가 하루씩 등록됩니다.
- 대시보드: 오늘 근무시간·인건비, 이번 달 누적 근무시간·인건비, 알바생별 필터와 개인 예상 급여.
- 급여명세서: 월·알바생별 근무일수·총시간·기본급·주휴수당(선택, 주 15시간 이상 간이 계산)·기타 수당·공제(3.3% 등)·실지급액.
  **카톡 전달용 텍스트 복사**와 **인쇄/PDF 저장**을 지원하고, 승인된 알바생은 본인 명세서만 볼 수 있습니다.

### 매장 데이터 구조 (같은 Firestore)

```
rooms/{storeRoomId}
  schema: 3, kind: "store", storeName
  staff: [ { id, name, color, bg, hourly, tel, joinedAt, active } ]
  joinRequests: { <id>: { name, tel, deviceId, status, staffId, hourly, requestedAt, decidedAt } }
  profileRequests: { <id>: { status, targetId, requesterId, requesterName, prevName, prevTel,
                             name, tel, createdAt, decidedByName, decidedAt } }
  storePins: { owner: "<sha256>" }          // PIN 평문 없음
  payrollSettings: { taxMode: none|3.3|custom, taxRate, weeklyAllowance, payDay, weeklyHours }
  events/{eventId}
    title, date, staffId, staffName, start, end, breakMin, wage, status, memo
```

배포된 보안 규칙(방 문서 get/create/update, events CRUD)을 그대로 쓰므로 **규칙 변경이 필요 없습니다.**

> 한계: 급여명세서는 저장하지 않고 열 때마다 계산합니다(수당·공제를 그 자리에서 조정해 복사·인쇄).
> 세금·주휴수당은 간이 계산이라 실제 신고·지급 금액과 다를 수 있습니다.

## 기간 일정 · 말로 입력 (2026-11-16 추가)

- 일정에 **종료일**을 넣으면 기간 일정이 됩니다. 달력의 기간 전체 날짜에 표시되고, 기간 중 아무 날을 눌러도 목록에 `11.27 ~ 11.30`으로 보입니다.
  다가오는 일정에서는 기간이 함께 표시되고, 오늘이 기간 안이면 `진행 중`으로 나옵니다. (기존 단일 날짜 일정과 호환)
- 일정·근무 화면의 **🎤 말로 입력하기**: 브라우저 음성 인식(ko-KR)으로 받은 문장을 해석해 칸을 채웁니다.
  - `"내일 오후 3시 첫째 치과"` → 날짜·시간·담당·분류(병원)·제목
  - `"11월 27일부터 30일까지 오사카 가족여행"` → 시작일·종료일·제목
  - `"음력 10월 12일 엄마 생일"` → 매년 음력 반복 + 담당·분류
  - 매장: `"내일 오전 9시부터 오후 6시까지 알바 근무"` → 날짜·출근/퇴근 시간
  인식된 원문과 해석 결과를 화면에 함께 보여 주고, 사용자가 확인·수정한 뒤 저장합니다.
  음성 인식을 지원하지 않는 환경에서는 안내 문구만 보여 주고 오류 없이 동작합니다.

## 구성원 이름·사진·날짜 앨범·미리 알림 (2026-11-16 추가)

- **이름 변경**: 관리자 설정에서 구성원 이름을 직접 고칩니다(다른 곳을 누르면 저장). 달력 칩·일정·프로필에 바로 반영됩니다.
  매장은 `알바생 관리`에서 같은 방식으로 이름을 바꿉니다. 일반 구성원·알바생이 스스로 바꿀 때는 **신상정보 변경 요청 → 관리자 승인**을 거칩니다.
- **인물 사진**: 구성원·알바생 사진을 고르면 브라우저에서 160×160 JPEG로 줄여 방 문서(`members[]`·`staff[]`의 `photoDataUrl`)에 저장합니다.
  칩·프로필 목록·근무 카드에 원형 사진으로 보입니다.
- **날짜 사진 앨범**: 날짜를 고르면 그 날 사진 카드가 나옵니다. 폴더를 만들거나 골라 사진을 여러 장 올리면
  긴 변 900px·JPEG 0.72로 줄여 `rooms/{roomId}/events/{docId}`에 `kind: 'photo'` 문서로 한 장씩 저장합니다(문서 1MB 제한 회피).
  썸네일을 누르면 전체화면 보기(이전/다음/삭제)가 열립니다.
- **미리 알림**: 일정에 없음/정시/10분 전/30분 전/1시간 전/전날을 지정할 수 있습니다.
  웹은 `Notification` 권한을 받은 뒤, 앱이 열려 있는 동안 배너와 알림을 띄웁니다.
  APK는 네이티브 알림(`AndroidApp.notify`)을 쓰고, 앱이 완전히 종료된 상태의 원격 푸시(FCM)는 별도 서버가 필요해 지원하지 않습니다.

## 편의 기능 5종 (2026-11-16 추가)

### 1. 매주 · 매월 반복 일정 (가족)
- 반복에 **매주**(요일 선택, 기본은 시작일 요일)와 **매월**(매월 같은 일자)을 추가했습니다.
- 매주는 고른 요일로 시작일을 맞춰 저장합니다(예: 11/17(화)에 '매주 목'을 고르면 11/19부터).
- 매월 29~31일처럼 그 일자가 없는 달은 **말일**로 계산합니다.
- 달력 표시·선택일 상세·다가오는 일정(D-Day)·미리 알림이 모두 매주/매월 발생을 계산합니다.
  D-Day는 일정마다 가장 가까운 한 번만 보여 줍니다.
- 저장 필드: `repeat: 'weekly' | 'monthly'`, `weekday: 0~6`(매주일 때).

### 2. 일정별 준비물 체크리스트 (가족)
- 일정 추가·수정·등록 요청 화면에서 준비물을 넣고 지울 수 있습니다(`checklist: [{ id, text, done }]`, 최대 30개·항목 40자).
- 선택일 상세 카드와 일반 구성원의 일정 상세에서 항목을 눌러 **완료 체크**합니다.
  체크는 `events/{id}.checklist` 한 칸만 merge 저장하므로 제목·시간·메모를 건드리지 않고,
  일반 구성원도 체크할 수 있으며 가족 모두의 폰에 바로 반영됩니다.
- 준비물이 있으면 일정 카드에 `준비물 2/3` 형태로 진행이 보이고, 승인 요청 카드에도 개수가 표시됩니다.

### 3. 알바생 출퇴근 체크 & 교대 인수인계 (매장)
- 오늘 근무 카드에 **[출근 체크] → [퇴근 체크]** 단추가 생깁니다. 누른 시각이 `actualStart` / `actualEnd`("HH:MM")에 저장되고
  실제 근무 시간이 함께 계산됩니다. 잘못 눌렀으면 [출근 취소] / [퇴근 취소]로 지웁니다.
  알바생은 본인 근무, 사장님은 모든 근무에 사용할 수 있고, 근무를 수정해도 기록은 유지됩니다.
- 매장 달력 아래 **📝 교대 인수인계** 카드에서 선택한 날짜의 특이사항을 한 줄씩 남깁니다.
  알바생·사장님 모두 남길 수 있고, 확인했으면 체크, 남긴 사람(또는 사장님)은 삭제할 수 있습니다.
  저장은 `rooms/{storeRoomId}/events/{docId}` 에 `kind: 'handover'` 문서로 하므로 보안 규칙 변경이 필요 없습니다.

### 4. 근무 변경 · 대타 요청 → 사장님 승인 (매장)
- 알바생이 자기 근무 상세에서 **[🙋 근무 변경 · 대타 요청]** 을 눌러 희망 시간·희망 대타 직원·사유를 보냅니다
  (희망 시간은 [1시간 늦게]·[2시간 늦게]·[1시간 일찍] 단추로 바로 채울 수 있어요)
  (`shiftRequests` 맵, 점 경로 업데이트로 다른 요청 보존).
- 사장님 **🔔 입장·승인** 창에 카드로 뜨고 **[승인]** 하면 같은 배치로 근무(`events`)의 담당·시간·시급이 바뀝니다.
  **[거절]** 하면 기존 근무가 그대로 유지됩니다.
- 알바생 화면의 근무 카드와 상세에 요청 상태(대기 중 / 승인됨 / 거절됨)가 표시됩니다.

### 5. 카톡 요약 복사 (가족 + 매장)
- 가족 달력 **[💬 카톡 요약 복사]** — `오늘 요약 복사` / `이번 주 요약 복사`(일~토). 날짜별로 `· 18:00 🏥 치과 — 첫째 (준비물 1/2)` 형태.
- 매장 달력 — `오늘 근무 복사` / `이번 주 근무 복사`(월~일). 근무 시간·인건비 없이 담당·시간·실제 출퇴근·인수인계 요약.
- 누르면 카톡에 바로 붙여넣을 수 있는 텍스트가 복사되고, 카드 안에 미리보기가 함께 뜹니다(클립보드가 막힌 환경은 직접 복사 안내).

### 초대 링크·캐시
- `?store=` 매장 초대 링크로 들어오면 **이 폰에 가족 코드가 이미 저장돼 있어도** 가족 화면 대신 매장 입장 화면이 열립니다.
  가족 방이 없는 알바생 폰은 예전처럼 가족 탭·가족 방이 보이지 않습니다(잠금 유지).
  가족 코드가 이미 있는 폰(가족이 매장 알바도 하는 경우)은 승인된 뒤에도 가족·매장 두 탭을 모두 봅니다.
- 자산 쿼리 버전 `20261117c`, 서비스워커 캐시 `family-calendar-v26` — APK v1.1에서도 재설치 없이 새 버전이 뜹니다.
