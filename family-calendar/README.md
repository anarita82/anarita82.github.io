# 우리 가족 달력 · 🏪 매장 달력

가족끼리 실시간으로 함께 쓰는 음력 지원 가족 달력입니다. 휴대폰 브라우저에서 열고 "홈 화면에 추가"하면 앱처럼 쓸 수 있어요.
주소: <https://anarita82.github.io/family-calendar/>

## 이전 버전(테스트)에서 달라진 점

- 저장 위치를 `localStorage`(그 기기에만)에서 **Firebase Cloud Firestore**(가족 공유 DB)로 옮겼습니다.
  한 사람이 일정을 추가·수정·삭제하면 가족 모두의 폰에 `onSnapshot`으로 즉시 반영됩니다.
- 처음 앱을 열 때 **가족 코드**를 한 번 입력하면 그 폰에 기억됩니다(코드를 아는 사람만 같은 달력을 봅니다).
- 한국어 음력·공휴일 계산, 구성원 6인 필터, 5개 카테고리, D-Day 목록 등 기존 기능은 그대로입니다.
- "가족 초대 링크 복사" 버튼으로 `?code=가족코드`가 붙은 링크를 만들어 가족에게 보낼 수 있습니다.
- "샘플 일정 지우기"는 제목이 `[샘플]`로 시작하는 일정만 지웁니다(가족이 넣은 일정은 그대로).

## 구성원·관리자·승인 (2026-11-16 추가)

| 역할 | 사람 | 할 수 있는 일 |
| --- | --- | --- |
| 메인 관리자 | 아빠 | 일정 즉시 등록·수정·삭제, 승인/거절, 구성원 추가·역할 변경, 아빠·엄마 PIN 변경 |
| 부매니저 | 엄마 | 일정 즉시 등록·수정·삭제, 승인/거절, 구성원 추가, 자기 PIN 변경 |
| 일반 구성원 | 외할머니·첫째·둘째·막내 + 추가한 인원 | 일정은 `일정 등록 요청`으로만, 내 이름·번호도 `신상정보 변경 요청`으로만 보낼 수 있고 아빠·엄마 승인 후 반영 |

- 앱을 열면 **"현재 사용자 선택"** 창에서 이 폰을 쓰는 사람을 고릅니다(폰에 기억).
  상단 프로필 배지를 누르면 언제든 바꿀 수 있습니다.
- **아빠·엄마는 4자리 관리자 PIN**을 넣어야 전환됩니다. 처음 PIN은 **`2026`** 이고,
  관리자 설정에서 각각 바꿀 수 있습니다. PIN 평문은 어디에도 저장하지 않고
  `SHA-256(방 ID + 구성원 ID + PIN)` 해시만 Firestore에 둡니다.
- 일반 구성원이 보낸 요청은 `요청 현황`(대기 중/승인됨/거절됨)으로 확인할 수 있고,
  관리자 화면 상단의 **🔔 승인 대기 N건**에서 승인·거절합니다.
  이름·휴대폰 번호 변경도 같은 승인함에서 처리합니다(아래 『구성원·알바생 신상정보 변경 승인제』).

## 구성원·알바생 신상정보 변경 승인제 (2026-11-16 추가)

이름·휴대폰 번호는 **당사자가 바로 바꾸지 못하고, 관리자 승인 뒤에 반영**됩니다.

| 화면 | 요청자 | 하는 일 |
| --- | --- | --- |
| 가족 `🙋 내 정보` | 일반 구성원(외할머니·첫째·둘째·막내·추가 인원) | 이름·번호를 고쳐 저장 → `profileRequests` 에 `pending` 으로 올라감 (members[] 는 그대로) |
| 가족 `🔔 승인 대기` | 아빠(메인 관리자)·엄마(부매니저) | 일반 일정 요청과 함께 **🙋 신상정보 변경 요청**(요청자 · 기존 → 변경)이 보이고, [승인]하면 `members[]` 에 반영·[거절]하면 그대로 |
| 가족 `📨 내 요청 현황` | 요청한 구성원 | 내 변경 요청의 대기 중/승인됨/거절됨을 확인 |
| 가족 `⚙️ 관리자 설정` | 아빠·엄마 | 구성원 이름·번호를 직접 고치면 예전처럼 **즉시** 반영 |
| 매장 `🙋 내 정보` | 알바생 | 이름·번호를 고쳐 저장 → `profileRequests` 에 `pending` (staff[] 는 그대로), 본인 화면에 대기/결과 표시 |
| 매장 `🔔 입장·승인 관리` | 사장님 | 입장 요청과 함께 **🙋 신상정보 변경 요청**이 보이고 [승인] 시 `staff[]` 반영 |
| 매장 `👥 알바생 관리` | 사장님 | 이름·번호를 직접 고치면 **즉시** 반영 |

- 한 사람이 대기 중인 변경 요청은 **1건**입니다. 다시 저장하면 그 요청이 새 내용으로 바뀝니다.
- 승인 시 `members[]`·`staff[]` 의 해당 항목만 이름·번호를 바꾸고, 색·역할·사진·입사일 등 나머지 값은 그대로 둡니다.
  (현재 문서를 트랜잭션 안에서 다시 읽어 적용하므로 그 사이 다른 저장을 지우지 않습니다.)
- 동시 요청 안전성: `requests`·`joinRequests`·`profileRequests` 맵은 **점 경로(dot-notation) 업데이트**로만 고칩니다.
  입장 요청 승인·거절도 맵 전체를 덮어쓰지 않아 다른 대기 요청이 지워지지 않습니다.
- 관리자 PIN은 예전과 같습니다(처음 `2026`).

## 데이터 구조 (Cloud Firestore)

```
rooms/{roomId}
  schema: 2, name: "우리 가족", createdAt
  members: [ { id, name, color, bg, role, tel, uids[] } ]  // role: admin|manager|member, tel: 번호(선택),
                                                          // uids: 이 구성원이 쓴 계정(uid) — 내보내기 차단용
  revokedUids: [ "<uid>", ... ]                  // 내보낸 구성원의 계정 — 가족 달력 접근 차단
  removedMembers: { <memberId>: { name, color, bg, role, tel, uids[], removedAt, removedBy } }
  pins: { dad: "<sha256>", mom: "<sha256>" }     // 4자리 PIN의 해시 (평문 없음)
  requests: {                                    // 일정 등록 요청 (맵 필드)
    <requestId>: { status: pending|approved|rejected, requesterId, requesterName,
                   title, date, time, members[], category, memo, repeat, lunar,
                   createdAt, decidedBy, decidedByName, decidedAt, eventId }
  }
  profileRequests: {                             // 신상정보(이름·번호) 변경 요청 (맵 필드)
    <requestId>: { status: pending|approved|rejected, targetId, requesterId, requesterName,
                   prevName, prevTel, name, tel,
                   createdAt, decidedBy, decidedByName, decidedAt }
  }
  events/{eventId}
    title, date(YYYY-MM-DD), time, members[], category, memo, repeat, lunar, createdAt, updatedAt
```

> 요청을 하위 컬렉션(`rooms/{roomId}/requests`)이 아니라 방 문서의 맵 필드로 둔 이유:
> 현재 게시된 보안 규칙이 `events` 하위 컬렉션만 허용하고, Firebase 콘솔이 재로그인을
> 요구해 규칙을 새로 게시하지 못했습니다. 방 문서 필드는 이미 허용된 경로라 규칙 변경
> 없이 동작하고, 예전 버전 앱은 이 필드를 무시합니다.
> 나중에 규칙을 바꾸게 되면 아래 한 줄을 `match /rooms/{roomId}` 안에 추가하면 됩니다.
> ```
> match /requests/{requestId} { allow read, create, update, delete: if request.auth != null; }
> ```

- `roomId` = `SHA-256("family-calendar-room:" + 가족코드)` 앞 32자리 — 코드 자체는 DB에 저장하지 않습니다.
- 보안 규칙(배포본):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rooms/{roomId} {
      allow get, create, update: if request.auth != null;   // 목록 조회는 막음
      // 구성원·PIN 해시·요청은 이 문서의 필드라 위 규칙으로 함께 커버됩니다.
      match /events/{eventId} {
        allow read, create, update, delete: if request.auth != null;
      }
    }
  }
}
```

- 앱은 원래 **익명 로그인**으로 접속하므로, 로그인하지 않은 요청은 거부되고 방 목록도 조회할 수 없습니다.
  같은 달력을 보려면 가족 코드를 알아야 해당 `roomId`에 접근할 수 있습니다.
- 2026-11-17 **이메일·구글 계정 로그인**을 붙였다가 잠시 미뤘습니다(화면에서 제거). 그때도 같은 `request.auth != null`
  조건을 그대로 만족했으므로 **보안 규칙은 지금도 바꾸지 않았습니다.**

## 🔐 계정 로그인 — 미뤄 둠 (2026-11-17 화면 제거)

계정 로그인(이메일·구글·카카오·네이버)은 **지금 화면에 없습니다.** 화면에는 상단 `🔐 로그인` 배지, 계정 창,
이메일 로그인·회원가입·비밀번호 재설정·구글 로그인·회원 탈퇴 단추, '누구신가요?' 창의 계정 로그인 안내가
**하나도 나오지 않고**, 가족 코드·매장 코드와 프로필 선택·관리자 PIN만으로 씁니다.

- Firestore 접근을 위해 **익명 인증은 그대로 자동**입니다(`signInAnonymously`, 화면에는 표시 없음).
  기기마다 익명 `uid`가 남아 **가족 내보내기·매장 퇴사 차단**이 지금처럼 동작합니다.
- 이전에 이 기기에서 이메일·구글 로그인을 했더라도 세션은 그대로 이어져 Firestore 접근에 쓰입니다.
- `cloud.js`의 계정 API는 지우지 않고 남겨 두어 나중에 화면만 다시 붙이면 됩니다:

```js
// cloud.js — 계정 API (지금은 화면에서 쓰지 않음)
FamilyCloud.onAuth(cb)                 // 로그인 상태 변화 구독 — app.js는 차단 상태 확인에만 사용
FamilyCloud.accountInfo()              // { signedIn, anonymous, uid, email, name, method, methodLabel }
FamilyCloud.signUpWithEmail(email, pw, name)
FamilyCloud.signInWithEmail(email, pw)
FamilyCloud.signInWithGoogle() / signInWithGoogleRedirect() / finishRedirectSignIn()
FamilyCloud.sendPasswordReset(email)
FamilyCloud.signOutAccount() / setAccountName(name) / authErrorHint(err)
FamilyCloud.ensureSignedIn()           // 로그인 상태 복원을 기다린 뒤 익명으로라도 접속
FamilyCloud.deleteAccount()            // 회원 탈퇴 — Auth 계정 삭제(user.delete)
```

- 토큰 교체 순간에 Firestore가 `permission-denied`를 낼 수 있어, 연결 전에 `getIdToken()`으로 토큰을 받아 두고,
  오류가 나면 **2.5초 뒤 한 번만** 자동으로 다시 연결합니다(`scheduleAutoRecover`).

## 🚪 회원 탈퇴 · 직원(구성원) 내보내기 (2026-11-17 추가)

### 1) 본인 회원 탈퇴 (계정 로그인을 미룬 지금은 화면에 없음)

| 화면 | 하는 일 |
| --- | --- |
| 계정 창 (로그인 상태) — **회원 탈퇴** | 로그인 화면을 다시 붙이면 나오는 단추. 두 번 확인 뒤 `user.delete()` 로 Firebase Auth 계정을 지웁니다 |
| 탈퇴 성공 | 익명 세션을 미리 받아 둔 뒤 화면을 새로 고칩니다(권한 오류로 남지 않음). 이 기기는 **익명 기기**로 계속 쓰고, 가족·매장 코드도 그대로예요 |
| 최근 로그인이 오래된 경우 | `auth/requires-recent-login` → **"[로그아웃]을 누른 뒤 같은 계정으로 다시 로그인하고 [회원 탈퇴]를 다시 눌러 주세요"** 안내 |
| 익명 기기 | 탈퇴할 계정이 없으므로 안내만 보여 줍니다 |

- 계정만 지우고 **가족·매장 데이터(일정·근무·급여)는 지우지 않습니다.**

### 2) 매장 — 직원 퇴사(강제 탈퇴), 사장님 전용

- `👥 알바생 관리`의 직원 옆 **[🚪 퇴사]** → 확인 → `retireStaff()`.
  - `staff[]` 항목을 **지우지 않고** `retired: true, retiredAt` 으로 남깁니다 → **과거 근무·급여명세서가 그대로 보존**됩니다(급여 목록에 `이름 · 퇴사`로 표시).
  - 그 직원의 `uid`(입장 승인 때 저장)와 `deviceId`를 각각 `revokedUids`·`revokedDevices` 에 넣습니다.
  - 그 폰은 다음 실시간 갱신(수 초) 안에 **"퇴사(탈퇴) 처리되어 매장에 접근할 수 없습니다"** 화면으로 바뀌고, 매장 일정·인수인계·급여 화면이 모두 가려집니다. 새로 고침·초대 링크(`?store=...`) 재입장·입장 요청도 막힙니다.
  - 계정·기기 정보가 없는(이 업데이트 전에 승인된) 직원은 차단이 확실하지 않다고 알려 주고, 그 폰의 새 요청은 [거절]하도록 안내합니다.
- **[복직]** → `restoreStaff()` : `retired` 를 풀고 차단 목록에서 빼서 다시 들어올 수 있게 합니다.
- **[✕ 완전 삭제]** → `purgeStaff()` : 목록에서만 지웁니다. 근무(events)·급여 기록은 남고 차단은 유지됩니다.
- 퇴사자·지난 근무는 `S.staff` 에 남아 있어 **급여명세서·근무 필터**에서 계속 볼 수 있고, 새 근무 등록의 직원 선택에서는 빠집니다.
- 퇴사 처리된 기기에서 새 입장 요청이 오면 승인함에 **⚠️ 경고**가 뜨고, [승인] 대신 **[복직]** 을 쓰도록 안내합니다.

### 3) 가족 — 메인 관리자의 구성원 내보내기

- `⚙️ 관리자 설정`의 구성원 줄 **[🚪 내보내기]**(아빠=메인 관리자만) → 확인 → `removeMember()`.
  - `members[]` 에서 빼고 `removedMembers` 에 이름·색·역할·번호·계정을 기록합니다(지난 일정은 그대로).
  - 프로필을 고를 때 그 폰의 **계정(uid)이 구성원에 묶여** 있어(`members[].uids`), 내보내면 그 uid 가 `revokedUids` 에 올라가 **"내보내기(이용 정지) 처리되어 가족 달력에 접근할 수 없습니다"** 화면이 뜹니다.
  - 계정 기록이 없는 구성원은 **이름만 목록에서 빠집니다**(그 폰에서 다른 구성원을 고를 수 있음을 안내).
- `🚪 내보낸 구성원` 목록의 **[되돌리기]** → `restoreMember()` : 구성원을 다시 넣고 차단을 풉니다.
- 메인 관리자 프로필로 들어와 있을 때는 잠그지 않아, 관리자가 스스로 잠기는 일을 막습니다.

> **보안 규칙 정합성**: 현재 게시된 규칙은 `request.auth != null` 만 보므로, 위 차단은 **앱(클라이언트)에서 강제**하는 것입니다.
> 코드를 아는 사람이 브라우저 콘솔로 직접 Firestore를 읽는 것까지 막지는 못합니다. 서버에서도 막으려면 규칙에
> `match /rooms/{roomId} { allow get, update: if request.auth != null && !(request.auth.uid in resource.data.revokedUids); ... }`
> 같은 조건을 넣어야 하는데, Firebase 콘솔 재로그인 문제로 이번에도 규칙은 게시하지 못했습니다(README 『보안 규칙』 참고).
> 그래서 **은퇴 직원에게는 매장 코드를 알려 주지 않고, 퇴사 시 코드 교체를 권장**합니다.

## 개인정보

공개 저장소입니다. 가족 실명·생년월일·전화번호·주소는 코드와 DB 어디에도 넣지 않았고, 구성원은 `아빠·엄마·외할머니·첫째·둘째·막내`로만 표시합니다.
Firebase 설정값(apiKey 등)은 웹 앱 식별용 공개 값이며, 접근 통제는 위 보안 규칙이 담당합니다.

## 구성원·알바생 휴대폰 번호 (2026-11-16 추가)

- **가족**: 관리자 설정에서 구성원마다 번호를 넣고(다른 곳을 누르면 저장), 구성원을 추가할 때도 번호를 함께 넣을 수 있어요.
  상단 프로필 배지 → **누구신가요?** 창의 **내 정보**에서 각자 자기 이름·번호를 고쳐 저장합니다.
  일반 구성원의 저장은 **아빠·엄마 승인 뒤에** 반영되고, 아빠·엄마는 바로 반영됩니다.
  구성원 목록에는 등록된 번호가 `📞 010-…`로 보이고 누르면 바로 전화(`tel:`)가 걸려요. 번호가 없으면 `미등록`으로 표시됩니다.
- **매장**: 알바생이 초대 링크로 들어와 이름과 번호를 넣고 입장을 요청하면,
  사장님 **🔔 입장·승인** 카드에 이름·번호가 함께 보이고 승인하면 `staff[]`에 번호가 저장돼요.
  알바생 관리에서 시급처럼 번호를 고칠 수 있고(📞 바로 전화, 사장님이 고치면 바로 반영), 알바생이 자기 화면의 **🙋 내 정보**에서 이름·번호를 고치면 **사장님 승인 뒤에** 반영됩니다.
  근무 카드(사장님 화면)와 급여명세서(화면·카톡 복사본)에도 연락처가 들어갑니다.
- 번호는 `010-1234-5678` / `02-1234-5678` / `1588-1234` / `+82 …` 형태로 자동 정리되고,
  **저장 위치는 Firestore 방 문서(`rooms/{roomId}`)뿐**입니다. 공개 저장소 코드에는 번호가 없습니다.

## 🏪 매장 캘린더 (2026-11-16 추가)

가족 달력과 **같은 앱**에서 상단 탭으로 오가지만, **Firebase 방 자체가 달라** 데이터가 섞이지 않습니다.

- 방 ID 소금(salt)이 다릅니다: 가족 `family-calendar-room:` / 매장 `family-calendar-store-room:`.

- 사장님: 매장 코드를 만들고, 초대 링크를 보내고, 승인·시급·급여명세서를 관리합니다 (PIN, 처음 `2026`).

- 근무: 알바생·시작/종료 시간·휴게(분)·적용 시급·상태(예정/근무완료/결근/취소)·메모.

- 대시보드: 오늘 근무시간·인건비, 이번 달 누적 근무시간·인건비, 알바생별 필터와 개인 예상 급여.
- 급여명세서: 월·알바생별 근무일수·총시간·기본급·주휴수당(선택, 주 15시간 이상 간이 계산)·기타 수당·공제(3.3% 등)·실지급액.
  **카톡 전달용 텍스트 복사**와 **인쇄/PDF 저장**을 지원하고, 승인된 알바생은 본인 명세서만 볼 수 있습니다.

### 매장 데이터 구조 (같은 Firestore)

```
rooms/{storeRoomId}
  schema: 3, kind: "store", storeName
  staff: [ { id, name, color, bg, hourly, tel, joinedAt, active,
             uid, deviceId,               // 퇴사 시 차단 대상 (입장 승인 때 저장)
             retired, retiredAt } ]       // 퇴사자 표시 — 항목을 지우지 않아 근무·급여 기록이 남음
  revokedUids: [ "<uid>", ... ]               // 퇴사(강제 탈퇴)된 계정 — 매장 접근 차단
  revokedDevices: [ "<deviceId>", ... ]       // 퇴사된 기기 — 매장 접근 차단
  joinRequests: { <id>: { name, tel, deviceId, uid, status, staffId, hourly, requestedAt, decidedAt } }
  profileRequests: { <id>: { status, targetId, requesterId, requesterName, prevName, prevTel,
                             name, tel, createdAt, decidedByName, decidedAt } }
  storePins: { owner: "<sha256>" }          // PIN 평문 없음
  payrollSettings: { taxMode: none|3.3|custom, taxRate, weeklyAllowance, payDay, weeklyHours }
  events/{eventId}
    title, date, staffId, staffName, start, end, breakMin, wage, status, memo
```

배포된 보안 규칙(방 문서 get/create/update, events CRUD)을 그대로 쓰므로 **규칙 변경이 필요 없습니다.**

> 한계: 급여명세서는 저장하지 않고 열 때마다 계산합니다(수당·공제를 그 자리에서 조정해 복사·인쇄).
> 세금·주휴수당은 간이 계산이라 실제 신고·지급 금액과 다를 수 있습니다.

## 기간 일정 · 말로 입력 (2026-11-16 추가)

## 편의 기능 5종 (2026-11-16 추가)

### 1. 매주 · 매월 반복 일정 (가족)
- 반복에 **매주**(요일 선택, 기본은 시작일 요일)와 **매월**(매월 같은 일자)을 추가했습니다.
- 매주는 고른 요일로 시작일을 맞춰 저장합니다(예: 11/17(화)에 '매주 목'을 고르면 11/19부터).
- 매월 29~31일처럼 그 일자가 없는 달은 **말일**로 계산합니다.
- 달력 표시·선택일 상세·다가오는 일정(D-Day)·미리 알림이 모두 매주/매월 발생을 계산합니다.
  D-Day는 일정마다 가장 가까운 한 번만 보여 줍니다.
- 저장 필드: `repeat: 'weekly' | 'monthly'`, `weekday: 0~6`(매주일 때).

### 2. 일정별 준비물 체크리스트 (가족)
- 일정 추가·수정·등록 요청 화면에서 준비물을 넣고 지울 수 있습니다(`checklist: [{ id, text, done }]`, 최대 30개·항목 40자).
- 선택일 상세 카드와 일반 구성원의 일정 상세에서 항목을 눌러 **완료 체크**합니다.
  체크는 `events/{id}.checklist` 한 칸만 merge 저장하므로 제목·시간·메모를 건드리지 않고,
  일반 구성원도 체크할 수 있으며 가족 모두의 폰에 바로 반영됩니다.
- 준비물이 있으면 일정 카드에 `준비물 2/3` 형태로 진행이 보이고, 승인 요청 카드에도 개수가 표시됩니다.

### 3. 알바생 출퇴근 체크 & 교대 인수인계 (매장)
- 오늘 근무 카드에 **[출근 체크] → [퇴근 체크]** 단추가 생깁니다. 누른 시각이 `actualStart` / `actualEnd`("HH:MM")에 저장되고
  실제 근무 시간이 함께 계산됩니다. 잘못 눌렀으면 [출근 취소] / [퇴근 취소]로 지웁니다.
  알바생은 본인 근무, 사장님은 모든 근무에 사용할 수 있고, 근무를 수정해도 기록은 유지됩니다.
- 매장 달력 아래 **📝 교대 인수인계** 카드에서 선택한 날짜의 특이사항을 한 줄씩 남깁니다.
  알바생·사장님 모두 남길 수 있고, 확인했으면 체크, 남긴 사람(또는 사장님)은 삭제할 수 있습니다.
  저장은 `rooms/{storeRoomId}/events/{docId}` 에 `kind: 'handover'` 문서로 하므로 보안 규칙 변경이 필요 없습니다.

### 4. 근무 변경 · 대타 요청 → 사장님 승인 (매장)
- 알바생이 자기 근무 상세에서 **[🙋 근무 변경 · 대타 요청]** 을 눌러 희망 시간·희망 대타 직원·사유를 보냅니다
  (희망 시간은 [1시간 늦게]·[2시간 늦게]·[1시간 일찍] 단추로 바로 채울 수 있어요)
  (`shiftRequests` 맵, 점 경로 업데이트로 다른 요청 보존).
- 사장님 **🔔 입장·승인** 창에 카드로 뜨고 **[승인]** 하면 같은 배치로 근무(`events`)의 담당·시간·시급이 바뀝니다.
  **[거절]** 하면 기존 근무가 그대로 유지됩니다.
- 알바생 화면의 근무 카드와 상세에 요청 상태(대기 중 / 승인됨 / 거절됨)가 표시됩니다.

### 5. 카톡 요약 복사 (가족 + 매장)
- 가족 달력 **[💬 카톡 요약 복사]** — `오늘 요약 복사` / `이번 주 요약 복사`(일~토). 날짜별로 `· 18:00 🏥 치과 — 첫째 (준비물 1/2)` 형태.
- 매장 달력 — `오늘 근무 복사` / `이번 주 근무 복사`(월~일). 근무 시간·인건비 없이 담당·시간·실제 출퇴근·인수인계 요약.
- 누르면 카톡에 바로 붙여넣을 수 있는 텍스트가 복사되고, 카드 안에 미리보기가 함께 뜹니다(클립보드가 막힌 환경은 직접 복사 안내).

### 초대 링크·캐시
- `?store=` 매장 초대 링크로 들어오면 **이 폰에 가족 코드가 이미 저장돼 있어도** 가족 화면 대신 매장 입장 화면이 열립니다.

  가족 코드가 이미 있는 폰(가족이 매장 알바도 하는 경우)은 승인된 뒤에도 가족·매장 두 탭을 모두 봅니다.

2. 사장님 PIN(처음 **2026**)을 넣으면 **그 기기에만** 상단 `💰 출납부` 탭이 생깁니다.
3. 탭을 열 때마다 PIN을 다시 물어봅니다. 가족·알바생 기기에는 탭이 생기지 않습니다.
4. 기기에서 끄기: 출납부 설정 → **[이 기기에서 출납부 숨기기]** (장부 내용은 서버에 남음).

### 데이터 구조
- 방: `rooms/{ledgerRoomId}` — `kind: 'ledger'`, `pinHash`(SHA-256, 평문 PIN 없음). 방 ID는 `family-calendar-ledger-room:` 소금 + 별도 코드로 계산해 가족·매장 방과 겹치지 않습니다.
- 내역: `rooms/{ledgerRoomId}/events/{docId}` — `kind: 'ledger'`, `type(income|expense)`, `area(store|personal)`, `category`, `amount`, `date`, `method(card|account|cash)`, `memo`, `repeatMonthly`, `source(manual|paste|auto)`.
- 배포된 보안 규칙(방 문서 get/create/update, `events` CRUD)을 그대로 쓰므로 규칙 변경이 필요 없습니다.

### 화면
- **이번 달 정산**: 총수입 / 총지출 / 순수익 + 구분 필터(전체·매장·개인).
- **달력 칸**: 그날 `+금액`(수입)·`-금액`(지출)을 만 단위로 줄여 표시(예: `+125만`, `-4.5만`). 날짜를 누르면 바텀시트에서 그날 내역을 보고 바로 등록·수정·삭제.
- **등록 항목**: 구분·영역·분류(매장매출·식자재·인건비·임대/공과금·카드·생활비·기타)·금액·날짜·결제수단·메모·**매월 반복**.
  매월 반복은 시작일의 "일"로 매달 올라가고, 그 일자가 없는 달은 말일로 계산합니다.
- **💬 이번 달 요약 복사**: 카톡에 붙여넣을 수 있는 한 덩어리 텍스트(총액·매장/개인·지출 많은 순·최근 지출).
- **CSV(엑셀) 내보내기**: BOM 포함 UTF-8. 웹은 파일 내려받기, 앱(1.5)은 `AndroidApp.saveTextFile()`로 `다운로드/우리 가족 달력/`에 저장.

### ① 문자·카톡 붙여넣기 자동입력 (웹·APK 공통)
`ledger.js`의 `parseMessages()`가 줄 단위로 나눠 날짜·금액·수입/지출·카드사/은행·내용·분류·영역을 추정합니다.

- 금액: `12,300원` 형태에서 고르되 `누적`·`잔액`·`한도`가 앞에 붙은 숫자는 제외하고 `승인·결제·입금·출금`과 가까운 값을 우선합니다.
- 수입/지출: `입금·환불·취소·매출·정산·충전·캐시백` → 수입, 나머지는 지출.
- 카드사/은행: KB국민·현대·삼성·신한·롯데·하나·우리·BC·NH농협·SC제일·IBK기업·카카오뱅크·케이뱅크·토스뱅크·카카오페이·네이버페이·토스페이·삼성페이 등 → 결제수단(카드/계좌) 추정.
- 날짜: `2026-11-17`, `11/17`, `11월 17일`, `어제`, `3일 전`을 읽고 없으면 오늘. 미래로 2일 이상 넘어가면 작년으로 봅니다.
- 이미 같은 날짜·금액·내용이 있으면 **"이미 있는 내역"**으로 표시하고 등록에서 빼 둡니다(눌러서 바꿀 수 있음).

### ② 폰 알림 자동 수집 (APK 1.5)
- `PaymentNotificationListener`(NotificationListenerService)가 알림에서 **금액(원)과 금융 키워드(결제·승인·입금·출금·이체·카드·은행·페이·환불·매출·정산)가 함께 있는 것만** 골라 로컬 큐(`SharedPreferences auto-entries/queue`, 최대 60건)에 쌓습니다.
- 웹앱은 `AndroidApp.getPendingAutoEntries()` → 파싱 → **📱 자동 수집 대기함**에 표시. **[모두 출납부에 넣기]** 또는 설정의 **바로 넣기** 토글로 반영하고, 넣은 뒤 `clearPendingAutoEntries()`로 큐를 비웁니다.
- 알림 접근 권한: 출납부 설정 → **[알림 접근 권한 설정 열기]** (`AndroidApp.openNotificationAccessSettings()`).
- 그 밖의 브리지: `hasNotificationAccess()`, `pendingAutoEntryCount()`, `saveTextFile(name, text)`.

### 보안 범위 (정확히)
- 이 기기에서만 탭이 보이고, 열 때마다 PIN을 물으며, PIN은 해시만 저장합니다. 가족·알바생 화면에는 탭·데이터가 나타나지 않습니다.
- 저장소는 공개 저장소의 웹앱이 쓰는 Firestore입니다. 앱 코드를 읽고 브라우저 콘솔로 직접 접근하는 사람까지 막는 암호화는 아닙니다(PIN 잠금은 앱 화면 잠금). 그 수준이 필요하면 규칙에 사용자 UID 제한을 넣고 로그인을 붙여야 합니다.

## 📱 화면 다듬기 — 모바일 사용성 (2026-11-17)

기능은 그대로 두고 **폰 화면(390×844)에서 더 쉽게** 쓰도록 화면을 정리했습니다.
자산 버전 `20261117z5`, 서비스워커 캐시 `family-calendar-v52`.

### 가족 달력
- **상단 바 다이어트**: 제목 + `⚙️ 설정` + 탭 + 내 프로필까지만. 연결 상태 문구(`가족 실시간 공유 중…`)는
  평소에 감추고, 연결이 끊겼을 때만 보입니다.
- **⚙️ 설정 시트** 하나로 모음: 🙋 내 정보·알림 · 🔑 관리자 설정 · 가족 초대(링크·코드) ·
  📖 사용 안내 · 샘플 일정 지우기 · 지금 연결 상태. 메인에 있던 안내 카드와 초대 버튼은 이리로 옮겼습니다.
- **달력 가독성**: 날짜 숫자 15.5px·굵게, 칸 속 일정 글씨 10px, 오늘(보라 알약)·선택(진한 보라 칸+테두리)·
  일요일/토요일/공휴일 색을 더 또렷하게. `[샘플]` 머리말은 칸 안에서 빼고 보여 줍니다.
- **선택일 카드**: 제목 줄에 `＋ 추가`(권한에 따라 `＋ 등록 요청`)를 두고, 일정은 3개까지 보여 준 뒤
  `일정 N개 모두 보기`로 바텀시트를 엽니다.
- **일정 추가 모달**: 제목 · 날짜 · 시간(종일) · 담당 가족만 먼저 크게. 종료일·카테고리·반복·알림·
  준비물·메모는 `＋ 더보기` 안으로 접고, **채워진 항목은 배지**로 보여 줍니다. 말로 입력이 기간·카테고리·
  반복을 채우면 자동으로 펼쳐집니다. 저장 줄은 스크롤해도 아래에 붙어 있습니다.
- **다가오는 일정**은 3개까지, `더 보기`로 12개까지. 사진 카드는 사진이 없는 날 한 줄로 접힙니다.
- 버튼 터치 영역 확대(닫기 44px·설정 42px·월 이동 40px), `＋ 일정 추가` 버튼은 오른쪽 아래로 옮겨 내용을 가리지 않습니다.

## ➕ 추가 캘린더 — 직접 만들고 초대하는 여러 캘린더 (2026-11-17 추가)

가족·매장 달력 외에 **원하는 캘린더를 직접 여러 개 만들어** 상단 탭으로 오가며 쓸 수 있습니다.
캘린더마다 **Firestore 방이 완전히 달라**(소금 `family-calendar-custom-room:`) 가족(`우리집2026`)·매장(`store-dfxh2`)·출납부(`ledger`)와 데이터가 섞이지 않습니다.

### 쓰는 법
1. 상단 탭 줄 오른쪽 **[＋ 추가]** → **새로 만들기** 또는 **초대 코드로 참여**.
2. **새로 만들기**: 캘린더 이름 · 아이콘(📅💼🏪⚽🎓✈️🏠🎯🎵🍽️🚗🐶) · 종류 · 관리자 PIN(비우면 `2026`) · 내 이름.
   - **📅 모임·일반형** = 일정·모임·행사 달력 (제목·날짜·시각·메모)
   - **🏪 매장·근무형** = 알바·근무시간·인건비·출퇴근 (근무자 목록 + 시급, 근무 등록, 출근/퇴근 체크)
3. 만든 캘린더는 **상단 탭에 아이콘·이름으로 생기고**, 탭을 누르면 그 캘린더 화면으로 바뀝니다.
   탭이 많아지면 탭 줄이 **가로로 스크롤**되고 [＋ 추가]는 오른쪽에 고정됩니다.
4. **⚙️ 설정**에서
   - **초대 링크 복사** (`?cal=코드`) / **코드 복사**
   - 내 이름(근무형은 *내 근무자*도) 저장
   - **이름·아이콘 바꾸기** — 관리자만
   - **관리자 PIN**으로 이 기기를 관리자로 열기
   - 근무형: **근무자 관리**(이름·시급 추가, 시급 수정, 목록에서 빼기)
   - **이 기기에서 캘린더 나가기** — 목록에서만 빼고 서버 기록은 그대로

### 초대 링크·참여
- 링크: `https://anarita82.github.io/family-calendar/?cal=<초대코드>` — 누르면 그 캘린더가 열리고, 처음이면 **참여** 확인 창이 뜹니다.
- 코드만 받았으면 [＋ 추가] → **초대 코드로 참여** → 코드 확인 → 참여.
- 없는 코드는 **"그 코드의 캘린더를 찾을 수 없어요"** 로 알려 줍니다.
- 이 기기에서 추가·참여한 목록은 `localStorage`(`family-calendar.custom.list.v1`)에 `code · name · icon · type` 으로 저장되고, 마지막에 보던 캘린더가 다음에 열 때 이어집니다.
